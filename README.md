## الإصدار الحالي v18

يصلح v18 رفض مجلد تثبيت الإصدارات الجديدة، ويضيف مراحل ملونة وتجهيز المكوّنات وتنبيهًا قبل إنهاء التثبيت مع نواقص. تبقى آلية التحديث الموقّع المجانية والمفتاح العام نفسه دون تغيير. حدّث مستودع الموقع بهذه الحزمة بعد نشر إصدار v18 وملفاته.

## تحديث 17.2 — القناة المجانية

هذا التحديث يستخدم mode=publisher-key. ملف release/signed-manifest.json موقّع بـRSA-3072، والمفتاح العام في release/update-public-key.xml. البناء يتحقق من التوقيع ومطابقة الإصدار ورابط المثبّت قبل نشر updates/latest.json. لا يحتاج هذا المسار شهادة ويندوز؛ المثبّت نفسه غير موقّع Authenticode. تعليمات الشهادة القديمة أدناه تخص المسار الاختياري المختلف.

المستخدمون على 17.2 يقرأون القناة الرسمية مباشرة من آخر إصدار ثابت في مستودع الإصدارات. لا تنشر ملف تحديث وهميًا، ولا ترفع المفتاح الخاص. لا تغيّر المفتاح العام الموجود إلا من خلال خطة انتقال موقّعة بالمفتاح السابق.

# File Orbit — الموقع الرسمي

موقع عربي/إنجليزي ثابت، مُجهز لحساب **Mohamedkh9** وللنشر على **Vercel**. لا يحتاج قاعدة بيانات أو مفاتيح API أو مكتبات npm خارجية. يدعم الجوال واتجاه RTL، ودائرة توضيحية تفاعلية، وصور واجهات حقيقية من البرنامج.

المطوّر: **محمد خالد** — **mohamedkhalida999@gmail.com**

## ابدأ من هنا

ستستلم حزمتين منفصلتين:

1. **FileOrbit-Website-GitHub.zip**: فكها وارفع **محتوياتها** إلى مستودع الموقع. يجب أن يكون `vercel.json` و`package.json` و`dist/` في جذر المستودع، لا داخل مجلد ZIP إضافي.
2. **FileOrbit-17.1-GitHub-Release-Assets.zip**: فكها وارفع ملفاتها إلى **GitHub Releases** في مستودع التنزيلات. لا ترفع ملفات EXE وZIP الكبيرة إلى مستودع الموقع أو عبر صفحة رفع ملفات الكود.

لا تتضمن حزمة الموقع كود برنامج ويندوز أو مفاتيح أو ملفات مستخدمين. لقطات البرنامج ببيانات تجريبية، وقد تعرض واجهات من إصدار سابق. الدائرة في الموقع توضيحية ولا تحوّل ملفات الزائر.

## 1. أنشئ مستودع التنزيلات

على https://github.com/Mohamedkh9 أنشئ مستودعًا عامًا باسم:

```text
file-orbit-releases
```

أضف README عند الإنشاء، ثم افتح **Releases → Draft a new release**:

- Tag: **v17.1** (بالضبط، لأن الموقع يستخدمه).
- Title: **File Orbit 17.1 — Preview**.
- ارفع ملفات حزمة Release Assets بعد فكها: المثبّت وZIP التشغيل والتراخيص ومواد إعادة الربط والدليل والبصمات.
- اذكر أن النسخة الحالية معاينة غير موقعة، وأن قناة التحديث التلقائي العامة غير مفعلة.
- انشر الإصدار وتحقق من تحميل المثبّت وملف SHA-256 دون تسجيل دخول.

الرابط الذي سيستخدمه الموقع:

```text
https://github.com/Mohamedkh9/file-orbit-releases/releases/download/v17.1/FileOrbit-Setup-17.1.exe
```

هذا الرابط مُجهز للنشر، لكنه لن يعمل حتى تنشئ المستودع والإصدار وترفع الملف فعليًا. لا تستخدم رابط مصدر GitHub ZIP مكان ملف تشغيل البرنامج.

## 2. أنشئ مستودع الموقع

أنشئ مستودعًا باسم:

```text
file-orbit-website
```

ارفع ملفات حزمة الموقع بعد فكها. يمكن أن يكون مستودع الموقع عامًا أو خاصًا بحسب تفضيلك وخطة الاستضافة؛ مستودع التنزيلات يجب أن يتيح الملفات للعامة. لا ترفع كود File Orbit لويندوز إلى أي منهما.

## 3. اربط الموقع بـVercel

1. سجّل الدخول إلى https://vercel.com باستخدام GitHub.
2. اختر **Add New → Project** ثم استورد `Mohamedkh9/file-orbit-website`.
3. اترك Root Directory جذر المستودع. إعدادات النشر موجودة في `vercel.json`:
   - Framework: **Other**.
   - Install Command: `node --version`.
   - Build Command: `node scripts/build.mjs`.
   - Output Directory: **dist**.
4. اضغط Deploy. لا تحتاج متغيرات سرية أو قاعدة بيانات.
5. استخدم رابط **Production** الثابت الذي يعرضه Vercel. لا تستخدم رابط Preview المؤقت كعنوان تحديث البرنامج.
6. تأكد أن الموقع وملفات التنزيلات متاحة للزائر دون شاشة تسجيل دخول. راجع Deployment Protection إن كان مفعّلًا على الرابط المستخدم.

Vercel يجهّز HTTPS؛ يمكن إضافة دومين خاص لاحقًا. راجع ملاءمة خطة Vercel لنشاطك؛ الخطة Hobby مخصصة للاستخدام الشخصي غير التجاري بحسب شروط المزوّد.

## الإعدادات التي قد تحتاج تغييرها

كل هوية الإصدار والروابط الأساسية في **site.config.json**:

| الحقل | الاستخدام |
|---|---|
| `github.owner` | الحساب: Mohamedkh9 |
| `github.websiteRepo` | اسم مستودع الموقع |
| `github.releasesRepo` | مستودع الملفات: file-orbit-releases |
| `siteOrigin` | اتركه فارغًا قبل أول نشر، أو أدخل HTTPS للدومين النهائي بدون مسار |
| `release` | رقم الإصدار والتاج وأسماء الملفات وحجم المثبّت وبصمته |
| `updates.enabled` | حاليًا false؛ لا تفعّله قبل تجهيز توقيع حقيقي |

عند النشر على Vercel يُستخدم `VERCEL_PROJECT_PRODUCTION_URL` تلقائيًا إن توفر لتوليد canonical وsitemap. يمكنك تثبيت الدومين يدويًا في `siteOrigin` بعد أول نشر. إعادة البناء تحفظ لغة الروابط وتمنع نشر بيان تحديث حي عند تعطيل القناة.

## التحديث التلقائي وشهادة التوقيع

شهادة HTTPS الخاصة بالموقع **لا تغني عن شهادة توقيع برنامج ويندوز**.

النسخة الحالية 17.1 **غير موقّعة رقميًا**، ولم يتوفر رابط الموقع النهائي أو شهادة الناشر. لذلك لم يُنشأ `dist/updates/latest.json` ولم ننشر بيانًا ببصمة وهمية. الموقع يوضح هذه الحالة للزائر، والتنزيل الحالي يدوي من GitHub Releases.

لتفعيل الخدمة بعد توفير الشهادة:

1. جهّز قناة File Orbit المدمجة برابط Production الثابت وبصمة شهادة الناشر، ثم أعد بناء البرنامج والمثبّت. أدوات ذلك في حزمة نشر البرنامج السابقة.
2. وقّع المثبّت الحقيقي وتحقق من صلاحية التوقيع في ويندوز.
3. من مجلد الموقع شغّل:

```powershell
.\scripts\prepare-signed-feed.ps1 -Installer 'C:\path\FileOrbit-Setup-17.2.exe' -ReleaseTag 'v17.2' -ReleaseNotes 'وصف الإصدار الجديد'
```

السكربت يرفض الملف غير الموقّع أو غير الموثوق، ثم يولّد البيان ويضبط القناة في الإعدادات.

4. ارفع **نفس المثبّت الموقّع** إلى الإصدار المحدد على GitHub أولًا، وحدّث بقية ملفات الإصدار والبصمات.
5. شغّل البناء وادفع التغييرات إلى GitHub حتى يعيد Vercel نشر الموقع. سيظهر البيان على `/updates/latest.json` مع منع التخزين القديم في الكاش.
6. جرّب تحديثًا موقّعًا فعليًا من النسخة السابقة على جهاز منفصل قبل تعميمه.

في النسخة الداعمة والمجهزة بالقناة، المستخدم لا يحتاج تحميل كل تحديث بنفسه. النسخ القديمة تحتاج ترقية أولى مرة واحدة. لا يُنشّط هذا الموقع التحديثات العامة وحده قبل إعداد البرنامج والشهادة.

## المعاينة والتعديل محليًا

يمكن فتح `dist/index.html` مباشرة لمراجعة الموقع. للمعاينة عبر HTTP والتعامل مع صفحات 404 بشكل مطابق أكثر:

```text
npm run build
npm run preview
```

ثم افتح http://127.0.0.1:8876 . يتطلب ذلك Node.js 20 أو أحدث، لكنه غير مطلوب للرفع اليدوي أو تشغيل نسخة الموقع المبنية؛ Vercel يوفر بيئة البناء.

```text
npm run check
```

يفحص الروابط المحلية والصفحات والملفات وبيانات الحساب وحالة بيان التحديث. لا يتطلب اتصالًا بخدمة خارجية.

الموقع لا يجمع الملفات ولا يضم تحليلات أو إعلانات أو خطوطًا خارجية. يحتفظ باللغة في localStorage. الاستضافة وGitHub لهما سياسات اتصال مستقلة. راجع بيان الخصوصية عند إضافة أي تحليلات أو خدمة لاحقًا.


## روابط File Orbit للتحميل

روابط الزائر تبدأ من `/download/windows` و`/download/runtime` و`/download/checksums`. يضبط `vercel.json` تحويلًا مؤقتًا إلى ملفات الإصدار الحالية. عند تغيير الإصدار في `site.config.json`، حدّث وجهات هذه الروابط في `vercel.json` أيضًا قبل الرفع؛ البناء يرفض الوجهات القديمة. لا تُخفِي إعادة التوجيه مصدر الملف في تفاصيل الاتصال. لإخفائه بالكامل يلزم تقديم الملفات من نطاق أو استضافة خاصة.

لا تتضمن صفحات الزائر ذكرًا لمنصة توزيع الملفات. لم تتغير حالة التوقيع أو التحديثات التلقائية.
